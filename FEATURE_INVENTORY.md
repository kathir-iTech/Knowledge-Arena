AUDIT and prior sessions described abandonment as "handled" — in code the user sees `Unexpected State` instead of `Battle Abandoned`. Needs a one-line fix (move check before live/paused).

2. **Workspace → Security Logs link is 404** — `src/app/executive/workspace/page.tsx` `router.push('/executive/security-logs')` vs real route `src/app/executive/security/page.tsx` (`ExecutiveSidebar` is correct). Prior inventories listed "Executive workspace" as complete — this link was missed.

3. **Announcements detail back-link is 404** — `src/app/executive/announcements/[id]/page.tsx` `router.push('/executive/announcements')` but no `src/app/executive/announcements/page.tsx` exists (only `[id]`). The page is only reachable via notification `link`; the sidebar does not link it either. It should route to `/executive/messages` or add an index.

4. **`assertQuizTransition` is dead** — `src/lib/battle-machine.ts:26` defines `assertQuizTransition` but no battle route imports it; routes check `status` inline and `firestore.rules:114 isLegalStatusTransition` is the real gate. ROADMAP V1.1 item "Strict state-machine enforcement" claims the helper should be wired into 11 battle routes — it isn’t.

5. **`login_success/login_failed/logout/rate_limited` were never written** — `SecurityEventType` `src/lib/security-log.ts:5` declares them, but `recordSecurityEvent` is only called via `logAuthFailure → invalid_token` and `logSecurityViolation → security_violation`. The executive Security Logs page filters for those events but will always show 0 for the declared types. Prior audit’s `insights` page counts them too — `AUDIT §1` flagged `Logging completeness` as an open V1.1 item, but the inventory now confirms the viewer code and the writer code are mismatched.

6. **`game.service.ts:evaluateQuestion` is entirely dead** — commented in AUDIT §6 as "client-side scorer" with a note that scoring is now server-only. This pass confirms zero importers via `grep from '@/services/game.service'` — the only callers are the stale comments. Prior session summaries sometimes still quoted its `SCORE_BASE 500 + timed bonus` as the live formula — the live formula is `battle-machine.computeCorrectScore` + `computeStreakBonus` (`SCORE_MAX 1000 / MIN 100` + `streak*multiplier`).

7. **Forge `MAX_TOTAL_IMAGES` budget was double-counted then fixed, but the fix introduces a per-document cap that wasn’t obvious** — AUDIT §6.4 lists the fix (removed duplicate increment, `extractPdfFile` now receives `remainingImageSlots`). What it doesn’t call out is that the new `PDFQuizGenerator.tsx` client loop caps each PDF at `MAX_SCANNED_PAGE_IMAGES 6` against the *shared* budget, so a single 80-page scanned PDF now only analyzes its first 6 scanned pages, not the densest 6 — a product decision, not a bug, but worth documenting for Kathir.

8. **PWA is not a PWA** — `docs/architecture.md §9` deployment diagram lists "PWA" and `ROADMAP.md §2.0` lists "PWA / mobile app" as V2.0. Prior sessions sometimes implied the app was installable. Code has `manifest.webmanifest` + icons + `display: standalone` but **no service worker, no `public/sw.js`, no `next-pwa`, no FCM**. Installability is accidental at best (no offline, no caching).

9. **Storage is not a backend** — `docs/architecture.md §1` diagram includes `Cloud Storage`, and `firebase.json` has `"storage": { "rules": "storage.rules" }`, but `AUDIT §2 Storage Dependency Note` correctly states the project uses **local file-based processing only** (browser `prepareDocuments` + data-URI JPEGs). Deploying with `firebase deploy --only storage` fails on Spark tier. Prior inventories that listed Storage as an active backend were wrong.

10. **AI engines: only `getQuizRecommendations` is live** — ROADMAP and `docs/architecture` contexts sometimes imply full prediction/knowledge/decision-support. In code, `getPredictionSummary`, `getRecommendationPrompt`, `getKnowledgeSummary`, `getDecisionSupportSummary` are **explicitly shelved** with `410 Gone` routes and header comments `PHASE 69: SHELVED — kept for future wiring`. The *one* live path is `getQuizRecommendations` (heuristic, not Gemini) via `GET /api/gladiator/recommendations`.

11. **`/executive/dashboard` is not a page** — `src/app/executive/dashboard/page.tsx:3` is `redirect('/executive/workspace')`. No test or sidebar links it; it exists for legacy bookmark compatibility. Prior inventories that listed it as a distinct dashboard double-counted workspace.

12. **`battleAuto-advance` no longer trusts client idleRef** — `src/app/api/battle/auto-advance/route.ts:68` now relies only on RTDB `presence/{quizId}/{commanderUid}` missing (Phase audit fix). Prior docs stating `commanderAbsentSinceRef` as a signal are stale; the client `LiveQuiz:601 commanderAbsentSinceRef` is only a local debounce placeholder.

13. **`middleware.ts` is not an enforcement layer** — `src/middleware.ts:46` comment `For now, pass through — client-side AuthContext handles enforcement` + `PORTAL_ROUTES` is never checked. Prior security reviews that cited middleware as "second layer" overstated it. Real layers are `ClientLayout` + per-portal `layout.tsx` + API `verify*` + `firestore.rules`.
